# Information Architecture v2 Implementation Plan & Audit

> **Phase 0 Deliverable** — Comprehensive audit of existing routes, storage keys, SEO architecture, 301 redirect map, and phased implementation roadmap for transitioning Beetrix360 to IA v2.

---

## 1. Executive Summary & Audit Findings

### 1.1 Architecture & Persistence Overview
- **Data Layer (`src/lib/types.ts`, `src/lib/db.ts`, `src/lib/content.ts`)**: Currently operates via an abstraction supporting DynamoDB and a local JSON fallback (`.data/content-store.json`). Pages have historically been keyed by slug (`PAGE:<slug>`). In IA v2, slugs repeat across different parent trees (e.g., `ecommerce` under `/web-design` and `/web-development`), requiring transition to full-path keying (`path`) with immutable `id`s.
- **Legacy Structure (`src/lib/site-structure.ts`, `src/content/site-structure.json`)**: Encodes 4 divisions, 21 services, and 66 sub-services (total 92 public routes including homepage `/`). All navigation and page hierarchy are derived from this legacy schema.
- **Dynamic Routing (`src/app/[slug]/page.tsx`, `src/app/[slug]/[sub]/page.tsx`)**: Next.js App Router uses 1-segment (`[slug]`) for divisions and services, and 2-segment (`[slug]/[sub]`) for sub-services. This will be replaced by a unified multi-segment catch-all route `src/app/[...segments]/page.tsx` supporting up to 3 segments while cleanly yielding priority to static routes.
- **Admin Studio (`src/app/admin/...`)**: Currently provides basic page and navigation editing, using server actions in `src/app/admin/actions.ts`. Will be extended with a 3-level tree view, full section editor, dedicated SEO tab with real-time live preview & JSON-LD validation, and menu constraint enforcement.

### 1.2 Current SEO Layer Audit
| SEO Element | Current State | IA v2 Target State |
|---|---|---|
| **Structured Data (`schema.ts`)** | `organizationSchema` and `websiteSchema` emitted in `RootLayout`. `webPageSchema`, `breadcrumbSchema`, `itemListSchema`, and `serviceSchema` emitted in `[slug]` and `[sub]`. | Unified JSON-LD graph per page with stable `@id` references. Hubs get `ItemList`, ready services get `Service`, all subpages get `BreadcrumbList`. FAQPage emitted only when ready and containing real FAQs. No synthetic reviews or ratings. |
| **`<head>` Metadata** | `title`, `description`, `canonical`, `openGraph`, `twitter` generated in layout and dynamic pages. Robots defaulted to `index: true, follow: true`. | Single title template avoiding brand duplication. Dynamic `robots` driven by `seo.robots` (initial placeholder pages start with `noindex, follow`). Absolute canonical via `NEXT_PUBLIC_SITE_URL`. Full Open Graph and Twitter card specifications. |
| **Navbar Crawlability** | Client component (`"use client"` in `Navbar.tsx`) with hardcoded markup. Links are in SSR HTML markup, but hardcoded and not responsive to content store. | Fully server-driven from `SITE#config / NAVIGATION` record. Pre-rendered in HTML as `<nav aria-label="Main">` with real `<a href>` tags without requiring client JavaScript execution. |
| **Font Loading** | Google Fonts (`Bricolage_Grotesque`, `Geist`, `Geist_Mono`, `Instrument_Serif`) imported via `next/font/google` in `layout.tsx` with `display: "swap"`. | Retained as-is (optimal setup). |
| **Image Optimization** | Currently does not use `next/image`; uses `<Ph>` CSS-striped divs and standard `<img>` tags. | Integrated `next/image` with required `alt`, explicit `width` and `height`, and priority hints only for above-the-fold hero images. |
| **Organization Settings** | Defined in `src/content/site.json`: name (`Beetrix360`), `formerName` (`Bee Social`), `foundingYear` (`2016`), `phone` (`+1 424 441 6042`), `url` (`https://www.beetrix360.com`). | Preserved and used exclusively in JSON-LD `Organization` nodes without inventing unverified facts. |

### 1.3 Content to Carry Over Audit
- Total keys in `.data/content-store.json`: 54 (1 home page, 2 site configs, 1 admin user, 50 `PAGE:` records).
- Detailed inspection of all 50 `PAGE:` records reveals that 16 records have 1 boilerplate section generated by an automated seed script on `2026-10-19T13:05:24Z` with `updatedBy: undefined` (e.g. "Comprehensive AI Chatbot Development workflows"). Zero pages have custom copy, tailored case studies, or manual edits created in Admin Studio.
- **Conclusion**: There is no custom human-authored content to carry over. All 168 pages in `src/content/ia-v2.seed.json` will be safely seeded with structured deterministic placeholder content.

> - **Single-Hop Enforcement**: The redirect engine and migration script refuse any redirect chain longer than one hop, collapsing or aborting if `target` is itself redirected.
> - **Active Redirect Records**: Exactly 90 301 redirect records will be written from the 92 historical routes.

## 4. Phased Implementation Plan (Phases 1–7)

### Phase 1 — Data Model Extension
**Goal**: Transition from slug-keyed storage to immutable `id` + unique `path`-based data structures.
- **Files to modify**:
  - `src/lib/types.ts`: Define extended `Page` type (`id`, `path`, `parentId`, `slug`, `h1`, `menuLabel`, `targetKeyword`, `seo`, `pageType`, `origin`, `division`, `sections`, `contentStatus`, `published`, `redirectFrom`, `updatedAt`, `updatedBy`). Define extended `SeoConfig` object, Section block types, and `NavigationRecord` with computed track span.
  - `src/lib/db.ts`: Add support for full path lookups (`getPageByPath`), redirect records (`REDIRECT:<normalizedPath>`), and ensure compatibility with both JSON fallback and DynamoDB.
  - `src/lib/content.ts`: Add helper functions to query pages by path, list published pages, and read navigation records.

### Phase 2 — Unified Routing & 301 Redirect Engine
**Goal**: Single catch-all route resolving 1–3 path segments with single-hop 301 redirect engine.
- **Routing & Redirect Resolution Strategy**:
  - Redirects will be resolved directly within the catch-all server route `src/app/[...segments]/page.tsx` via `db.ts` (`getRedirect(path)`). This avoids Next.js Edge runtime incompatibilities with AWS SDK / DynamoDB that occur with middleware.
  - Returns real 301 (or 308) HTTP redirect status to the normalized canonical path.
  - Automatically collapses any redirect chains to a single hop.
  - Programmatically rejects self-referential / identity redirects (`source === target`).
  - Trailing slashes are 301-redirected to the canonical form without a trailing slash.
- **Files to add/modify**:
  - Add `src/app/[...segments]/page.tsx`: Resolves 1–3 path segments from `db.ts`. Checks redirect records first. Returns 404 (`notFound()`) for unknown or unpublished pages (unless authenticated admin preview).
  - Remove legacy `src/app/[slug]/page.tsx` and `src/app/[slug]/[sub]/page.tsx` (superseded by `[...segments]`).
  - Static route priority confirmed: `/admin`, `/api`, `/sitemap.xml`, `/robots.txt`, `/llms.txt`, and homepage `/` take precedence over the catch-all.

### Phase 3 — Database Migration Script
**Goal**: Deterministic, idempotent migration script to populate 168 pages, navigation, and redirects.
- **Homepage Protection**:
  - The seed record for `/` specifies `seo.robots: { index: false, follow: true }`. The migration overrides this: `/` **must stay `index: true, follow: true`**.
  - The migration must **never** replace existing homepage content (`PAGE#home:CONTENT` or `src/content/homepage.json`). The seed record for `/` only supplies baseline SEO fields.
- **Automated Backup & Navigation Preservation**:
  - First action of `--apply`: Dumps the entire store (including existing `SITE#config:STRUCTURE` and `PAGE#home`) to `.data/backups/backup-<timestamp>.json`.
  - Writes the new navigation model to `SITE#config:NAVIGATION`.
  - Legacy `SITE#config:STRUCTURE` is retained in the backup and preserved as an archive in storage without premature deletion.
- **Dynamic Hand-Edited Carry-Over Check**:
  - Dynamically scans the target store (local JSON or DynamoDB) for any page record where `updatedBy` is defined or `updatedAt` is different from the original seed run timestamp (`2026-10-19T13:05...`).
  - If any hand-edited page is detected, its content is automatically carried over to the mapped IA v2 path and marked `contentStatus: "ready"`, or execution safely aborts with a detailed list of modified records for review.
- **Redirects Ingestion**:
  - Ingests all 90 active redirect records (omitting identity rows `/` and `/digital-marketing`).
  - Enforces single-hop collapse and identity refusal.
- **Idempotency**: Running `scripts/migrate-ia-v2.ts --apply` multiple times results in zero duplicate records and zero diff.
- **Files to create/modify**:
  - `scripts/migrate-ia-v2.ts`: With `--dry-run` and `--apply` flags.

**Goal**: Comprehensive meta tags, unified JSON-LD graph, and strict crawler controls.

## 5. Risk Assessment & Verification Strategy
1. **Zero Indexation Leakage**: All 168 seeded pages initialize with `robots: { index: false, follow: true }`. They will NOT appear in `sitemap.xml` or `llms.txt` until explicitly reviewed and marked ready in Admin Studio.
2. **Zero 404 Disruption**: All 92 existing indexed URLs have deterministic 301 mappings. No redirect loops or multi-hop chains.
3. **Zero Data Loss**: Automated full backup to `.data/backups/` before applying migrations.
4. **Local Sandbox Isolation**: Strict usage of local JSON content store (`.data/content-store.json`). Zero remote DynamoDB or S3 mutations.
